٢ — لماذا AcadeGate فرصة للمورد؟

المشتري الأكاديمي (طالب ماجستير/دكتوراه · باحث · مسؤول مختبر) يشتري بشكل متكرر لكنه مشتت بين واتساب ومجموعات فيسبوك ومواقع عامة لا تفهم احتياجاته.

عميل مقصودباحث يبحث عن منتج محدد، لا متصفح عشوائي
ثقة أعلىضمان حجز المبلغ حتى تأكيد الاستلام
ظهور متخصص١٥ قسماً أكاديمياً لا منافسة «سوبر ماركت»
الجملة التي تهمّك: العميل يصل إليك وهو داخل رحلة بحث علمي (فكرة → مشرف → مختبر → معدات → كتابة). عندما يحتاج منتجاً، المتجر جزء طبيعي من المسار — وليس إعلاناً منفصلاً يتجاهله.

ما الذي نخسره اليوم بدون منصة؟

  • طلبات عبر قنوات غير منظمة بدون سجل واضح
  • خلافات على التحويل والاستلام بدون وسيط محايد
  • صعوبة الوصول لطلاب الجامعات خارج شبكة علاقاتك الحالية
  • غياب تقييم وسمعة رقمية أكاديمية لمنتجاتك

٣.٤ حقول إضافية (للدليل والكتالوج المتقدم)

٣.٥ تجربة المشتري داخل المتجر

  1. يدخل أقسام المتجر من الصفحة الرئيسية
  2. يتصفح منتجات القسم المعتمدة
  3. يفتح صفحة المنتج: صورة، سعر، وصف، بيانات البائع
  4. ينشئ طلباً (بعد تسجيل الدخول) أو يتواصل معك عبر الرسائل / بيانات التواصل
  5. يدفع عبر المسار المتاح (تحويل يدوي حالياً · Paymob جاهز تقنياً)
  6. بعد الاستلام يؤكد التسليم ليُفرَج المبلغ المحجوز

٦ — آلية الضمان (Escrow) بالتفصيل

الضمان هو أقوى حجة بيع لديك أمام العميل المتردد، وأمام إدارتك أيضاً: يقلل النزاعات ويبني ثقة تسرّع إغلاق الصفقة.

٤.١ دورة الطلب كاملة

1إنشاء طلبالمشتري يختار المنتج · السعر يُقرأ من قاعدة البيانات
2دفع / تحويليدوي الآن أو Paymob عند التفعيل
3حجز المبلغحالة paid_held · أنت تؤكد استلام التحويل اليدوي
4التنفيذتشحن / تسلّم المنتج وتتواصل داخل التطبيق
5الإفراجالمشتري يؤكد الاستلام · تُحرَّر القيمة للبائع

٤.٢ حالات الدفع وحالات الطلب

حالات الدفع

  • pending_payment — طلب أُنشئ ولم يُحجز بعد
  • paid_held — محجوز / تحويل مؤكد
  • released — أُفرج للبائع بعد تأكيد الاستلام
  • refunded — مسار استرداد عند الحاجة

حالات الطلب

  • pending — بانتظار الدفع/التأكيد
  • paid — البائع أكّد التحويل اليدوي
  • delivered — المشتري أكّد الاستلام
  • cancelled — إلغاء وفق القواعد

٧ — آلية الشراكة: المورد ↔ AcadeGate

شراكة تشغيلية واضحة: أنت تملك المنتج والسعر والتنفيذ — نحن نملك القناة والجمهور والثقة الرقمية.

٥.١ ماذا نقدّم نحن

  • قناة وصول مباشرة لطلاب الدراسات العليا والباحثين ومسؤولي المختبرات
  • ١٥ قسماً تصنيفياً أكاديمياً + بحث داخل المنصة
  • بوابة مقدم خدمة: منتجاتك + الطلبات الواردة + الرسائل
  • نظام ضمان Escrow يقلل اعتراضات «دفعت ولم يصل» / «وصلت ولم أدفع»
  • مراجعة محتوى قبل النشر (حماية سمعة الجميع)
  • إمكانية الظهور ضمن مسار البحث الذكي كجزء من حزمة الباحث
  • إمكانية استيراد/مزامنة كتالوج (مسار إداري — WooCommerce وغيره حسب الاتفاق)
  • مساحات إعلان على الصفحة الرئيسية (للشركاء المميزين — عبر إدارة المنصة)

٥.٢ ماذا تقدّم أنت

  • منتجات حقيقية بأسعار واضحة وصور ومواصفات صادقة
  • التزام بتحديث التوفر والرد على الطلبات خلال وقت متفق عليه
  • تنفيذ الشحن/التسليم وفق ما تعرضه في المنتج أو الاتفاق مع المشتري
  • التعامل المهني مع التحويلات اليدوية حتى تفعيل الدفع الإلكتروني الكامل
  • الالتزام بسياسات المحتوى وعدم بيع منتجات مخالفة أو مقلّدة

٨ — ماذا تفعل داخل التطبيق عملياً؟

٦.١ مسار المورد: مطالبة الملف ثم إدارة الكتالوج

  1. إنشاء حساب واختيار دور تاجر / مورد (merchant) — بدون هذا الدور لن يظهر زر المطالبة
  2. من المتجر افتح صفحة موردك في الدليل (ابحث باسم شركتك)
  3. اضغط مطالبة هذا الملف (Claim this profile)
  4. عبّئ الاسم القانوني وصفتك والبريد الرسمي، وارفع إثبات تمثيل إلزامي (سجل تجاري / خطاب / بطاقة)
  5. انتظر مراجعة AcadeGate — يصلك إشعار عند الموافقة أو الرفض
  6. بعد الاعتماد تظهر حالة موثّق ومُدار (Managed Verified)
  7. من زر ترتيب بيانات الملف حدّث التواصل والوصف، ثم أضف منتجات/صوراً (ترتبط تلقائياً بصفحة موردك)
  8. بديل/مكمل: بوابة مقدم الخدمة → متجري لإدارة المنتجات والطلبات الواردة
  9. التواصل مع المشتري · تأكيد التحويل اليدوي · تجهيز الشحنة · إغلاق الضمان بعد الاستلام
مهم: الدليل العام ليس اعتماداً. شارة «موثّق» تظهر فقط بعد التحقق من تمثيلك للمنشأة (Managed Verified).

٦.٢ شاشة «متجري» تتضمن

تبويب منتجاتي

  • إضافة منتج جديد
  • فتح التفاصيل / الحذف عند الحاجة

تبويب الطلبات

  • كل الطلبات التي أنت بائعها
  • تمييز الدفع اليدوي / الإلكتروني
  • زر تأكيد استلام التحويل
  • مراسلة المشتري فوراً
لا تحتاج موقعاً جديداً من الصفر: إن كان لديك متجر WooCommerce أو كتالوج جاهز، يمكن بحث مسار استيراد/مزامنة عبر الإدارة لملء المنصة بسرعة بدل الإدخال اليدوي لكل صنف.

٩ — نموذج الإيرادات بشفافية (الوضع والمقترح الأساسي)

نوضح الوضع كما هو في المنتج اليوم، وما هو مقترح للشراكة التجارية — بلا مبالغة.

٩.١ ما يعمل اليوم

  • إنشاء منتجات وطلبات داخل Firestore + عربة متعددة الموردين
  • تحويل يدوي + تأكيد البائع + ضمان حتى تأكيد الاستلام
  • تكامل Paymob موجود في البنية ويمكن تفعيله بعد الترتيبات القانونية

٩.٢ المقترح التجاري الأساسي

  • ميزة الرائد: الموردون الأوائل يبنون تقييماً وسمعة وكتالوجاً يظهر أولاً في الأقسام الفارغة نسبياً
